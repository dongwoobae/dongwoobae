## 🧭 **개발 관점**

저는 웹사이트를 단순히 화면과 기능의 조합으로 보지 않고, 각 도메인의 운영 문제를 줄이는 도구로 설계하려고 합니다.

복지센터 홈페이지에서는 사진 홍보와 개인정보 보호가 함께 중요하다고 보고, 얼굴 자동 블러와 수동 보정 파이프라인을 구현했습니다. 교회 홈페이지에서는 매주 반복되는 설교·주보·갤러리 운영 부담을 줄이기 위해 YouTube 설교 자동 동기화, HWP 주보 구조화, 관리자 CMS를 설계했습니다.

AI가 코드를 빠르게 생성할 수 있는 시대일수록, 중요한 것은 “무엇을 왜 만들어야 하는가”라고 생각합니다. 저는 사용자의 업무 흐름과 운영자의 반복 작업을 먼저 이해하고, 그 도메인에서 실제로 감탄할 만한 차별화 기능을 제품 안에 녹이는 개발자를 지향합니다.

### 🌟 기술 하이라이트

실서비스를 운영하며 특히 공들인 엔지니어링.

#### 🗺️ 모두의 캠퍼스 — 이동약자 중심 배리어프리 지도

배리어프리라는 정체성을 단순 정보 나열이 아니라 기능으로 구현.

- **경사도 오버레이 + 법적 기준 시각화**: 경로 구간별 경사도를 색상으로 표시하고, 휠체어 접근 **법정 기준 1/12을 범례로 명시**해 이동약자 관점의 정보 제공.
- **관리자 폴리곤 직접 드로잉**: 지도 위에서 건물 폴리곤을 직접 그려 신규 건물을 등록·편집. 단순 CRUD가 아닌 지도 인터랙션 구현.
- **Overpass API 동기화 (3-서버 순차 폴백)**: OpenStreetMap Overpass 서버 3개를 순차 시도해 외부 API 장애에 대응. **소프트 삭제** 건물은 sync가 재추가하지 않도록 충돌 방지.
- **Papago NMT 자동 다국어화**: 관리자가 한국어로 입력하면 등록 시점에 **en/zh로 자동 번역(`Promise.all` 병렬)** 후 저장, 한 / English / 中文 i18n 제공.

#### 🖼️ 안강 섬김 — 게시 사진 얼굴 자동 블러 (개인정보 보호)

복지센터 사진 게시 시 어르신·이용자 얼굴이 노출되는 문제를 업로드 파이프라인에서 자동 처리.

- **클라이언트 감지 + 서버 블러 분리**: 브라우저에서 `face-api.js`(TinyFaceDetector)로 얼굴 좌표를 감지하고, 서버(`sharp`)에서 해당 영역만 추출 → 강블러(`blur(28)`) → 원위치 합성. EXIF 회전·리사이즈 스케일을 보정해 좌표를 정확히 매핑.
- **2-Phase 업로드 파이프라인**: TF.js WebGL 백엔드가 단일 스레드라 **얼굴 감지는 순차**, **R2 업로드는 병렬(`Promise.all`)**로 분리해 다중 업로드 성능을 확보 (Server Action 직렬화를 피하려 업로드만 API Route로 분리).
- **원본/블러 이중 저장 + 토글**: `original/`·`blurred/` 두 버전을 보관해 사진별 블러 on/off 및 **수동 블러 영역 편집**까지 지원.
- TF.js 텐서 메모리 누수를 objectURL 해제 + GC yield로 완화.

#### 📺 영천중앙교회 — YouTube 설교 자동 동기화 (WebSub 푸시)

새 설교가 올라오면 **폴링 없이 실시간으로** 등록되도록 YouTube WebSub(PubSubHubbub)로 이벤트 기반 파이프라인을 구축.

- **WebSub 구독**: 채널 피드를 Google PubSubHubbub 허브에 구독(`hub.mode=subscribe`, `verify=async`, `hub.secret`). 업로드 발생 시 허브가 콜백으로 **Atom 알림을 푸시** → 주기적 폴링 불필요.
- **콜백 보안 2겹**: ① 구독 검증(GET)은 **우리 채널 토픽일 때만 `hub.challenge`를 에코**해 임의 토픽 구독을 차단, ② 알림(POST)은 **`X-Hub-Signature`(HMAC-SHA1)를 원문 바이트 기준 timing-safe 비교**로 위조 차단.
- **수신 → 큐 연결**: Atom payload에서 `yt:videoId`를 파싱해 업로드면 **QStash `ingest-video` 잡 발행**으로 자막·요약 파이프라인에 연결. 삭제 엔트리·파싱 실패는 별도 분기 처리.
- **구독 자동 갱신**: WebSub 리스는 만료되므로 **QStash cron으로 재구독(`websub-renew`)**해 구독 끊김을 방지.
- **백필 경로**: 과거 영상·누락분은 예배유형별 재생목록을 순회해 **기존 ID와 대조 후 신규만 삽입**하는 보조 동기화로 보완.

#### 🤖 영천중앙교회 — 설교 AI 요약 파이프라인

설교 자막을 Gemini로 구조화 요약. **Vercel 서버리스(장기 실행 프로세스 불가) 환경에서 Upstash QStash 메시지 큐로 다단계 비동기 파이프라인**을 구성.

- **QStash 단계 체이닝**: `ingest-video → fetch-transcript → summarize`를 각각 독립 잡(서버리스 함수)으로 분리하고 QStash로 연결. 잡 엔드포인트는 **HMAC 서명 검증**으로 보호.
- **구조화 출력**: Gemini `responseSchema`로 한 줄 소개(핵심 성경구절 포함) · 핵심 요점 8~12개 · **타임스탬프 챕터 분할**(주제 전환 기준, 구간별 상세 요약)을 JSON 스키마로 강제.
- **동시성 제어(claim)**: Postgres CTE `UPDATE ... RETURNING`으로 설교 1건을 원자적으로 선점해 **중복 요약 차단** + stale pending 회수.
- **재시도 + 지수 백오프(서버리스식)**: 프로세스를 붙잡고 sleep할 수 없으므로 **QStash 지연 발행(`delay`)으로 백오프를 구현**(`attempts < 3`, `5·3ⁿ분`). 정기 재시도·WebSub 갱신은 **QStash cron 스케줄(멱등 `scheduleId`)**로 수행. 자막 영구 부재 건은 제외해 API 쿼터 소진 방지.
- 모델 fallback 체인으로 일시 장애 대응.

#### 🎨 영천중앙교회 — AI 설교 썸네일 생성

유튜브 원본 썸네일(목사님 정면 1프레임)을 **디자인된 설교 썸네일로 자동 생성**하는 관리자 기능. "AI 배경 + 코드 텍스트 합성" 하이브리드 파이프라인.

- **하이브리드 합성**: AI가 한글을 못 그리는 문제를 피하려 배경만 AI로 만들고 **모든 글자는 코드로 오버레이**. 배경 = OpenAI `gpt-image-2`(1280×720, 스타일별 프롬프트 + 설교 키워드 테마), 텍스트 = `@vercel/og`(Satori)로 한글 폰트 임베드 후 CSS 합성.
- **3가지 스타일**: ①정통형(제목+성경구절) ②후킹형(Gemini가 요약에서 후킹 헤드라인 생성) ③인물컷형(목사님 누끼 합성).
- **누끼 비용 0원 설계**: remove.bg로 배경 제거 시 ⓐ원본 하단 **자막 밴드를 먼저 crop**해 자막이 누끼에 딸려오는 문제 제거, ⓑ원본이 저해상도(480×360)임을 이용해 **preview 사이즈(무료 등급)**로 처리 → 화질 손실 없이 유료 크레딧 미사용.
- **성경구절 자동 추출**: 요약문에서 `책이름 장:절` 정규식으로 추출(실패 시 관리자 입력 유도).
- **운영 안전장치**: 관리자 모달 수동 생성(비용 경고), 후보 이력 보존(`thumbnailCandidates`), 확정 시 `customThumbnailUrl` 적용하되 **원본 유튜브 썸네일은 폴백 보존**(되돌리기 가능).
